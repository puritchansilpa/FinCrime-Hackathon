# Entity Resolution / Record Linkage and ML Alert Triage for Sanctions/PEP Screening False-Positive Reduction

Evidence legend used below: **[PEER]** = peer-reviewed journal/conference; **[WP]** = working paper / preprint / thesis (not peer-reviewed); **[REG]** = central bank / official research; **[VENDOR]** = vendor or bank marketing / press release (unaudited, methodology rarely disclosed). Items marked *(background knowledge; DOI given, not re-fetched this session)* are canonical references cited from established literature rather than from a page fetched during this research.

## 1. Fellegi-Sunter probabilistic record linkage and its mapping to SAME / REVIEW / DIFFERENT

### Takeaway
Fellegi-Sunter (1969) is the canonical decision-theoretic frame for screening adjudication: per-field m/u probabilities give additive log-likelihood "match weights"; two thresholds create three zones (link / possible link -> clerical review / non-link), which map directly onto SAME / REVIEW / DIFFERENT. Under an asymmetric cost (false clearing of a true sanctions hit is far worse than a false escalation), the lower threshold should be set so the "non-match" zone has near-zero false-negative rate, pushing uncertainty into REVIEW.

### Cited Findings
- Original paper: Fellegi, I.P. & Sunter, A.B. (1969), "A Theory for Record Linkage", JASA 64(328):1183-1210 [PEER] *(background knowledge)* — [DOI 10.1080/01621459.1969.10501049](https://doi.org/10.1080/01621459.1969.10501049). The model fixes tolerated error rates (mu for false links, lambda for false non-links) and derives two thresholds on the likelihood ratio; pairs between thresholds go to clerical review. This is optimal in the sense of minimising the review region for given error rates *(background knowledge)*.
- m-probability = P(field agrees | true match); u-probability = P(field agrees | non-match). These are the model parameters; true match status is unknown so they must be estimated — [Splink: Fellegi-Sunter topic guide](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html); [Mismo FS concept page](https://nickcrews.github.io/mismo/concepts/fs).
- Field weights are log ratios: agreement weight = log2(m/u), disagreement weight = log2((1-m)/(1-u)); total match weight is the sum across fields (Splink calls this the "match weight"; converts via prior to a match probability) — [ABS m and u probabilities](https://www.abs.gov.au/AUSSTATS/abs@.nsf/2f762f95845417aeca25706c00834efa/93275A3BB3B61601CA257BE900110E67); [Splink FS guide](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html).
- The standard model assumes conditional independence of field comparisons given match status, which is "rarely true in practice" (e.g. name and gender, city and postcode correlate) — [Splink FS guide](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html).
- EM estimation of m/u is attributed to Winkler (1988); Winkler (1993) imposed additional constraints on probabilities to improve estimation — [arXiv 1603.07816 (Steorts et al.)](https://arxiv.org/pdf/1603.07816); [Statistics Canada Splink case study](https://publications.gc.ca/collections/collection_2024/statcan/11-522-x/CS11-522-2022-1-2-eng.pdf). Winkler also introduced the Jaro-Winkler string comparator (prefix bonus) used ubiquitously in name screening *(background knowledge)*.
- Practical modern estimation (Splink, UK Ministry of Justice, open-source): estimate u directly by random sampling of record pairs (almost all random pairs are non-matches), then EM only for m; correct u "anchors" EM — [Splink training rationale](https://moj-analytical-services.github.io/splink/topic_guides/training/training_rationale.html); [Robin Linacre EM intuition](https://robinl.github.io/em_intuition/).
- Blocking: EM run on a single blocked set only sees pairs agreeing on the blocking key, so Splink trains in multiple passes with different blocking rules (e.g. block on DOB to estimate name parameters) — [Splink training rationale](https://moj-analytical-services.github.io/splink/topic_guides/training/training_rationale.html). Blocking rules must be loose enough to capture all potential matches but tight enough to be computationally feasible — [Statistics Canada (2022/2024)](https://publications.gc.ca/collections/collection_2024/statcan/11-522-x/CS11-522-2022-1-2-eng.pdf); see also [Scaling Bayesian PRL with post-hoc blocking, arXiv 1905.05337](https://arxiv.org/pdf/1905.05337).
- Multi-file generalization of FS (linking >2 systems jointly, applied to homicide records) — [Sadinle & Fienberg, arXiv 1205.3217](https://arxiv.org/pdf/1205.3217) [PEER, JASA 2013].

### Inferences
- Direct mapping: weight >= upper threshold -> SAME (true match / escalate as hit); weight <= lower threshold -> DIFFERENT (auto-clear); between -> REVIEW (human/L2). With asymmetric costs, the FS error tolerance on false non-links (lambda) should be set near zero, which lowers the lower threshold and enlarges REVIEW; auto-clearing is only allowed where the evidence of non-identity is strong (e.g. conflicting DOB, nationality, gender — fields with high disagreement weight).
- FS weights are inherently explainable per field ("DOB disagreement contributed -6.6 bits"), which suits audit/regulator explanation requirements better than opaque scores.
- In screening, u-probabilities should be name-frequency-aware (agreement on "Mohammed" or "Wang" is weak evidence; agreement on a rare surname is strong) — Splink supports term-frequency adjustment (per its docs; not fetched in detail this session).

### Gaps
- No source found that formally applies FS three-zone thresholds to sanctions/PEP adjudication with reported numbers; the mapping is inference.
- Full text of the Fellegi-Sunter paper and Winkler's papers was not fetched; details marked background knowledge.

## 2. Customer-side entity resolution across internal systems (no shared key), clustering, golden record

### Takeaway
Customer-side ER (deduplicating the screened party across CRM/core banking/cards etc.) relies on blocking + pairwise scoring + clustering. Naive transitive closure (connected components) over-merges — one bad link fuses unrelated people, and shared phone/address links (households, corporate service addresses) are not identity. Golden records are built by per-attribute survivorship rules with provenance.

### Cited Findings
- Connected components = transitive closure of match links; simplest clustering, high recall but weak precision because one wrong link can merge large unrelated clusters; more robust alternatives include correlation clustering and center/star clustering — [Rahm & Peukert, Large-Scale Entity Resolution (Leipzig)](https://dbs.uni-leipzig.de/file/large-scale-ER.pdf).
- Practical guardrails: cap cluster size; route records that bridge two clusters to review; keep each match as its own record with evidence and do not assert strong identity until match is certain; log provenance (source, method, time) for survivorship — [Atlan: What is entity resolution](https://atlan.com/know/ai-agent/ontology/what-is-entity-resolution/) [VENDOR/blog].
- Golden-record ("entity consolidation") problem: merging each cluster into a canonical record using match/merge rules; Deng et al. auto-generate transformation rules with human confirmation of rule groups and report ~40% improvement in golden-record precision — [Deng et al., "Entity Consolidation: The Golden Record Problem", arXiv 1709.10436](https://arxiv.org/abs/1709.10436v3) [WP/academic, MIT/Tamr].
- Shared attributes as relationship, not identity: Senzing's example links two records with different name variants as *related* entities due to shared address and phone, distinguishing relation from resolution — [Senzing](https://senzing.com/redhorse-graphaware-entity-resolved-knowledge-graphs/) [VENDOR]. Data-quality caveat: phone stored with vs without country code causes missed links — [Atlan KG for financial crime](https://atlan.com/know/ai-agent/ontology/knowledge-graph-use-cases-for-fraud-detection-and-financial-crime/).
- Survivorship is commonly implemented as "most trusted source wins" / most recent / most complete per attribute in MDM tools (e.g. SAS DataFlux entity-resolution jobs) — [SAS DataFlux docs](https://support.sas.com/documentation/onlinedoc/dfdmstudio/2.9/Content/dfU_T_EntityResJob.html).

### Inferences
- For screening, model household vs individual explicitly: shared address/phone should be a "related party" edge (useful for network context and for screening relatives/close associates of PEPs) but must not raise identity weight on its own; give those fields low u-specificity or exclude them from identity scoring.
- Screen the golden record but keep source-level values (aliases, all DOBs seen) because survivorship can discard the very variant that matches a list entry; a conservative approach screens all surviving and non-surviving variants.

### Gaps
- No peer-reviewed source found specifically on household-vs-individual resolution in bank KYC data.

## 3. Published ML approaches to screening alert triage, with reported results

### Takeaway
Peer-reviewed, quantified evidence specific to sanctions/PEP *alert* classification is thin. The strongest independent evidence is a Federal Reserve Board working paper (2025) showing LLM-based matching cut false positives 92% vs the best fuzzy baseline with +11% detection, and a 2024 Frontiers paper showing NLP-enhanced fuzzy matching reduced false negatives but *increased* false positives. Most headline figures (60-92% FP reduction) come from vendors/banks and are not independently audited. Deep entity matching (DeepMatcher 2018, Ditto 2020) is strong background but benchmarked on product/citation data, not watchlists.

### Cited Findings
**Independent / academic**
- Allen & Hatfield (Sept 2025), "Can LLMs Improve Sanctions Screening in the Financial System? Evidence from a Fuzzy Matching Assessment", FEDS 2025-092 [REG/WP]: compared four LLM families (plus smaller variants) vs common fuzzy-matching algorithms on name and address similarity; across realistic thresholds LLMs reduced false positives by 92% on average and increased detection by 11% vs the best fuzzy baseline; LLMs >4 orders of magnitude slower; a cascade (fuzzy/exact for easy cases, escalate uncertain cases to LLM) was ~2x faster than pure LLM with comparable accuracy; smaller models performed comparably — [Federal Reserve FEDS page](https://www.federalreserve.gov/econres/feds/can-llms-improve-sanctions-screening-in-the-financial-system-evidence-from-a-fuzzy-matching-assessment.htm); [FRBSF summary](https://www.frbsf.org/research-and-insights/publications/board-of-governors/2025/10/can-llms-improve-sanctions-screening-financial-system-evidence-fuzzy-matching-assessment/). (Dataset details not obtained — PDF not parseable this session.)
- Kim & Yang (Nov 2024), "Accuracy improvement in financial sanction screening: is NLP the solution?", Frontiers in AI [PEER]: baseline Levenshtein-based screening with false-positive rate >90%; NLP (e.g. distinguishing individual vs organisation names to set fuzzy weights) significantly reduced false negatives but generated more false positives — a sensitivity/FP trade-off; 70% threshold -> many FPs, 99% -> FN risk — [Frontiers full text](https://www.frontiersin.org/articles/10.3389/frai.2024.1374323/full); [PMC copy](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11621073/).
- Jullum et al. (2020), J. Money Laundering Control 23(1):173-186 [PEER]: XGBoost (gradient-boosted trees) on DNB bank data to predict probability a transaction/alert is reported; using investigated-but-not-reported alerts as negatives *and* uninvestigated normal transactions improved results; clearly outperformed bank's existing approach on a new fair metric. Transaction-monitoring, not name screening, but the closest peer-reviewed bank-data alert-triage GBT study — [Emerald](https://emerald.com/insight/content/doi/10.1108/JMLC-07-2019-0055/full/html); [NR preprint PDF](https://publ.nr.no/1583921963/jullum_et_al_2020_money_laundering.pdf).
- Srinivasan, "SENTINEL ML" (SSRN preprint) [WP]: explainable stacking ensemble; reports 1.0% FPR at 93.5% recall on 13,000 records built from only 124 public SDN entries (OFAC/UN/EU/OFSI) — small synthetic set, not peer-reviewed; note recall 93.5% would be unacceptable for auto-clearing — [SSRN](https://papers.ssrn.com/sol3/Delivery.cfm/7266559.pdf?abstractid=7266559&mirid=1). Other conceptual/thesis works: [Bhanushali, SSRN](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7454301); [NCI Dublin MSc thesis, NLP+ML name screening](https://norma.ncirl.ie/9864/1/gayatrimaheshjadhav.pdf).
- Siamese LSTM for company-name disambiguation at Intesa Sanpaolo (2023), with active learning reaching saturation with fewer labels than random sampling — [arXiv 2303.05391](https://arxiv.org/pdf/2303.05391v1) [WP].
- OpenSanctions (2025) argues embedding-based deep learning is good at candidate generation (recall) but less suited to discerning false positives; its logic-v2 matcher is rule-based/symbolic and explainable — [OpenSanctions logic-v2](https://www.opensanctions.org/articles/2025-09-11-logic-v2); [Name matching in sanctions screening](https://www.opensanctions.org/articles/2025-06-24-name-matching) [non-profit data provider].

**Deep entity matching background**
- DeepMatcher: Mudgal et al., "Deep Learning for Entity Matching: A Design Space Exploration", SIGMOD 2018 [PEER] *(background knowledge)* — [DOI 10.1145/3183713.3196926](https://doi.org/10.1145/3183713.3196926): RNN/attention attribute-summarisation matchers; strong gains on textual/dirty data, little gain over classical ML on clean structured data *(background knowledge)*.
- Ditto: Li et al., "Deep Entity Matching with Pre-Trained Language Models", VLDB 2021 (arXiv 2020) [PEER]: fine-tunes BERT/DistilBERT/RoBERTa as sequence-pair classification; up to ~29-31% F1 over prior SOTA (v1 abstract said up to 19%; cite version); matches previous SOTA with at most half the labels; 96.5% F1 matching company datasets of 789K vs 412K records — [VLDB PDF](https://www.vldb.org/pvldb/vol14/p50-li.pdf); [arXiv 2004.00584](https://arxiv.org/abs/2004.00584v3).
- Active learning for EM: SIGMOD 2020 benchmark finds AL with fewer labels can match supervised learning — [arXiv 2003.13114](https://arxiv.org/pdf/2003.13114); ALMatcher [arXiv 2211.00311](https://arxiv.org/abs/2211.00311v1); Battleship [arXiv 2311.15685](https://arxiv.org/pdf/2311.15685); ALER (2026) [arXiv 2601.20664](https://www.arxiv.org/pdf/2601.20664).

**Vendor / bank claims (unaudited)**
- HSBC + Google Cloud AML AI (2023, transaction monitoring, not name screening): 2-4x more suspicious activity detected and ~60% fewer alerts; HSBC's own write-up frames it as 60% fewer *false positive* cases; Google states >95% of system alerts are false positives in first-line review — [Google Cloud blog](https://cloud.google.com/blog/topics/financial-services/how-hsbc-fights-money-launderers-with-artificial-intelligence); [Google press release, June 2023](https://www.googlecloudpresscorner.com/2023-06-21-Google-Cloud-Launches-AI-Powered-Anti-Money-Laundering-Product-for-Financial-Institutions); [HSBC views](https://hsbc.com/news-and-views/views/hsbc-views/harnessing-the-power-of-ai-to-fight-financial-crime) [VENDOR]. Note the alerts-vs-false-positives inconsistency across sources.
- Silent Eight: Standard Chartered partnership (2018, "Screening Optimisation" — ML/NLP true/false match recommendations for name screening) — [SC press release](https://www.sc.com/en/press-release/weve-partnered-with-regulatory-technology-firm-silent-eight); HSBC name screening across all risk types (2022) and expansion to transaction screening "Automated Alert Closure" (Feb 2024) — [PR Newswire 2024](https://prnewswire.com/news-releases/silent-eight-announces-expansion-of-partnership-with-hsbc-to-provide-transaction-screening-solutions-302067562.html). Approach: replicate analyst reasoning from historical case decisions. No public FP-reduction figures found [VENDOR].
- SymphonyAI NetReveal: Nordic financial group 83% FP reduction / 24,000 alerts eliminated — [case study](https://www.symphonyai.com/resources/case-study/financial-services/nordics-financial-group-effective-compliance-transaction-filtering-and-false-positive-reduction/); claims of Spanish bank -91.8% FPs and large US bank -92% FPs with "100% true positive retention" — [SymphonyAI screening](https://www.symphonyai.com/financial-services/screening); datasheet target >=70% FP reduction — [NetReveal transaction screening datasheet](https://www.symphonyai.com/resources/data-sheet/financial-services/netreveal-transaction-screening/) [VENDOR].
- Quantexa: "75% reduction in false positives" and "99% match accuracy" with no named client/method — [Quantexa AML](https://www.quantexa.com/solutions/aml/); Danske Bank case study qualitative only — [casestudies.com](https://www.casestudies.com/company/quantexa/case-study/danske-bank-maximizes-the-value-of-data-with-decision-intelligence) [VENDOR].
- Precisely (entity resolution): US retail bank cut false positives investigators must pursue by 58% — [Precisely case study](https://www.precisely.com/app/uploads/2020/05/CS_Blinded_US-Based-Retail-Bank_200505_E_final.pdf) [VENDOR].
- ComplyAdvantage: Holvi halved time spent remediating false positives — [bestpractice.ai](https://bestpractice.ai/ai-use-cases/case-studies/financial-services/holvi-reduces-time-spent-investigating-false-positives-for-customer-risk-using-ai-platform-complyadvantage) [VENDOR].
- Socure: siamese network with LSTM layers for name matching plus DOB/address/national ID — [Socure blog](https://www.socure.com/blog/power-of-machine-learning-for-better-compliance-outcomes) [VENDOR].

### Inferences
- Common architecture across sources: high-recall candidate generation (fuzzy/phonetic/embedding) -> secondary classifier (GBT/logistic/ensemble or LLM) using secondary identifiers (DOB, nationality, gender, address, entity type) -> human review for the uncertain band. The Fed cascade result supports tiering expensive models to uncertain cases only.
- Gradient-boosted trees on engineered comparison features (FS-style per-field similarity features) are the pragmatic default; Jullum et al. show the value of using closed (non-reported) alerts as labelled negatives — directly analogous to using L1 "false positive" dispositions as training labels (with care about label noise/bias from historical analyst decisions).
- Vendor FP-reduction numbers cluster at 50-92%, but baselines (rule-tuning vs ML), period and true-positive retention are rarely disclosed; treat as marketing.

### Gaps
- Napier: no case study with figures found. Feedzai: not searched in depth; no screening figures found.
- No peer-reviewed study found that applies learning-to-rank specifically to sanctions alert prioritisation.
- No public benchmark dataset of real sanctions screening alerts exists (privacy); most academic work uses synthetic name-variant data.
- Fed paper dataset composition/recall numbers not extracted (PDF unparseable here).

## 4. Extreme class imbalance, asymmetric costs, ~100% recall thresholds, abstention

### Takeaway
True matches are typically far below 5% of alerts (>90-95% are false positives per Kim & Yang 2024 and Google 2023). The right framing is cost-sensitive selective classification: auto-decide only where the model is confident, abstain (REVIEW) otherwise, with the auto-clear threshold set on held-out data so that recall of true matches is ~100% (with a confidence bound), accepting reduced coverage/automation rate.

### Cited Findings
- Base rates: >95% of system-generated alerts are false positives at first review (Google, 2023) — [Google press release](https://www.googlecloudpresscorner.com/2023-06-21-Google-Cloud-Launches-AI-Powered-Anti-Money-Laundering-Product-for-Financial-Institutions) [VENDOR]; FP rate >90% in sanctions screening — [Kim & Yang 2024](https://www.frontiersin.org/articles/10.3389/frai.2024.1374323/full) [PEER].
- Chow (1970) reject option: the Bayes-optimal rule rejects when the top posterior falls below 1 - epsilon, where epsilon is the cost of rejection relative to error — [Dietterich 2021 slides on rejection](https://web.engr.oregonstate.edu/~tgd/talks/dietterich-deeplearn-2021-rejection.pdf); original: Chow, IEEE Trans. Inf. Theory 16(1), 1970 *(background knowledge)* — [DOI 10.1109/TIT.1970.1054406](https://doi.org/10.1109/TIT.1970.1054406). Applying Chow requires calibrated probabilities; alternatively learn the rejection function directly — [Optimal strategies for reject option classifiers, arXiv 2101.12523](https://ar5iv.labs.arxiv.org/html/2101.12523).
- Selective classification risk-coverage trade-off, including the extreme case where zero risk must be guaranteed — [El-Yaniv & Wiener, JMLR 2010](https://jmlr2020.csail.mit.edu/papers/volume11/el-yaniv10a/el-yaniv10a.pdf) [PEER]. Franc et al. formulate "bounded improvement" (guaranteed selective risk, maximal coverage) without specifying a reject cost — [arXiv 2101.12523](https://ar5iv.labs.arxiv.org/html/2101.12523). Selective classification for deep nets with a user-specified risk guarantee: Geifman & El-Yaniv, NeurIPS 2017 *(background knowledge)* — [arXiv 1705.08500](https://arxiv.org/abs/1705.08500).
- Vendor claim of "100% true positive retention" alongside 92% FP reduction (large US bank) illustrates the industry target of zero recall loss — [SymphonyAI](https://www.symphonyai.com/financial-services/screening) [VENDOR].
- SENTINEL ML's 93.5% recall at 1% FPR shows that optimising a balanced metric yields unacceptable miss rates for screening — [SSRN](https://papers.ssrn.com/sol3/Delivery.cfm/7266559.pdf?abstractid=7266559&mirid=1) [WP].

### Inferences
- Threshold procedure: on a held-out labelled set, choose the auto-clear threshold t_low as the score below which zero true matches fall (or below the lowest true-match score minus a margin); report an upper confidence bound on miss rate (e.g. with 0 misses among n true matches, the 95% one-sided bound is ~3/n — "rule of three", standard statistics, not from a fetched source). This makes the number of labelled true matches, not total alerts, the binding constraint.
- Conformal / risk-controlling prediction (e.g. conformal risk control, Learn-then-Test) can give distribution-free guarantees on false-clear rate; I found no fetched source applying this to screening — treat as a recommended technique to verify.
- Handle imbalance via class weights / focal loss / undersampling of easy negatives, but evaluate at the operating point (recall@~100%, automation rate = coverage) rather than AUC/F1.
- Three outputs map cleanly: SAME (high-confidence match, still human-confirmed before blocking), DIFFERENT (auto-clear only below the recall-guaranteeing threshold), REVIEW (abstention band). Monitor drift and re-validate thresholds when lists change (new designations shift score distributions).

### Gaps
- No peer-reviewed paper found reporting recall-constrained thresholding specifically on sanctions alert data.
- Conformal methods for screening: no direct source found.

## 5. Knowledge-graph / network-based entity resolution for financial crime

### Takeaway
Industry practice (Quantexa, Senzing, Neo4j, Sayari) uses entity-resolved graphs to add context (shared addresses, directors, ownership chains) to alerts and to resolve parties across internal and external data; this is mostly evidenced by vendor material, with little independent measurement. Academic multi-source ER (graph clustering, multi-file FS) provides the methodological foundation.

### Cited Findings
- Senzing builds an entity-resolved graph by matching addresses, SSNs, phones, emails; exports to Neo4j for knowledge graphs; integrated into NICE Actimize AML — [Senzing/GraphAware](https://senzing.com/redhorse-graphaware-entity-resolved-knowledge-graphs/) [VENDOR].
- Neo4j: graph-based AML investigations following activity beyond the alert — [Neo4j](https://neo4j.com/?p=435608) [VENDOR].
- Sayari: top US bank used knowledge-graph ER for sanctions/trade (cites 90-95% analyst time on false positives as industry benchmark, no measured reduction) — [Sayari case study](https://sayari.com/resources/case-studies/top-bank-sanctions-trade/) [VENDOR].
- Quantexa Decision Intelligence: contextual entity resolution + network for AML/screening; claims 75% FP reduction (unattributed) — [Quantexa AML](https://www.quantexa.com/solutions/aml/); HSBC partnership on financial-crime tech — [A-Team Insight](https://a-teaminsight.com/hsbc-takes-on-financial-crime-tech-challenge-with-ai-approach-from-quantexa/?brand=rti) [VENDOR].
- Graph clustering for ER (connected components vs correlation/center clustering) — [Rahm & Peukert](https://dbs.uni-leipzig.de/file/large-scale-ER.pdf); joint multi-file linkage — [Sadinle & Fienberg arXiv 1205.3217](https://arxiv.org/pdf/1205.3217) [PEER].
- DNB later moved to graph neural networks for AML, citing Jullum et al. as prior ML alerting work — [arXiv 2307.13499](https://web3.arxiv.org/pdf/2307.13499) [WP].

### Inferences
- For alert adjudication, graph context is useful as features (e.g. "customer's director is linked to a listed entity", ownership >=50% per OFAC 50% rule) and as evidence for analysts, but identity decisions should still rest on per-attribute evidence; relationship edges must be kept distinct from identity merges.

### Gaps
- No peer-reviewed quantitative study found measuring FP reduction from knowledge-graph ER in sanctions screening.
- Feedzai, Napier, ComplyAdvantage graph capabilities not verified.
